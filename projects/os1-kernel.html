A small operating system kernel for RISC-V (RV64IMA), written in C++ and assembly and running on the QEMU emulator.

What it does

The kernel boots, sets up its own trap handling and memory, and then runs a user program on top of it. User code talks to the kernel only through system calls, which are available both as a C API and as C++ classes.

  • Threads — preemptive, time-sliced, with a FIFO scheduler and a sleep queue.
  • Semaphores — for synchronisation between threads.
  • Memory allocator — the kernel's own, used for every allocation including new and delete.
  • Console — interrupt-driven, backed by circular buffers.
  • C++ API — Thread, Semaphore, PeriodicThread and Console classes over the C calls.

How it works

Every system call is an ecall that lands in a single trap routine written in assembly. It saves the registers and hands control to handleTrap, which deals with system calls, timer ticks and console interrupts. The scheduler then decides which thread runs next, and a short assembly routine switches to it.

make clean
make qemu

What I learned

Writing the code that runs below everything else: no standard library, no output until the console works, and bugs that show up as a silent hang. Most of the work was in getting the trap path and the context switch exactly right.
